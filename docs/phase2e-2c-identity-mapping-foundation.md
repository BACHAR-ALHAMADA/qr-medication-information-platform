## Implemented boundaries and migration

Identity.Infrastructure configures `identity.authentication_issuers` and `identity.external_staff_identities`. Exact `text COLLATE "C"` unique keys cover all lifecycle states. Keys are bounded to 1-1024 UTF-8 bytes, with control/blank rejection and conservative HTTPS issuer storage checks. URI shape and registry enablement do not authenticate anyone; no case folding, trimming, aliases or Unicode normalization occurs. An independent ordinal trusted-issuer allowlist is copied into each resolver.

Restrictive same-Identity foreign keys use ON UPDATE/DELETE RESTRICT. Mapping ownership, issuer/subject and opaque IDs are immutable. Issuers default disabled; mappings default disabled. Unlinked mappings are terminal tombstones. Invoker-rights triggers reject ordinary DELETE/TRUNCATE and metadata rewrites; database timestamps and positive bigint revisions are maintained on every update, including no-ops. Overflow fails and revisions roll back with transactions. EF concurrency uses returned revisions and rejects stale writes. Privileged administrators can bypass these safeguards; fixtures exercise such powers only for synthetic teardown or overflow setup in rolled-back transactions.

One forward-only migration, `20261111233123_IdentityMappings`, creates only these tables, their constraints/indexes and two invoker-rights guard functions. Down fails explicitly without dropping data. Existing migrations and their review SQL are unchanged. New objects are owned by `qr_platform_owner`; both new tables ENABLE/FORCE RLS with zero policies and no reader/setup grants. Existing roles, role memberships, eight policies and membership revision behavior are unchanged. No SECURITY DEFINER function is added. Catalog assertions now expect three migrations, nine application tables and eight FORCE RLS tables on a fresh target.

`SyntheticIdentityMappingSession` accepts only the named disposable `qr_medication_ci` database and directly connected `qr_ci_admin` superuser. It opens read-only Repeatable Read and rolls back on disposal with an independent bounded cleanup token; failed cleanup clears the connection pool. This is an explicit privileged test target restriction, not production credential attestation or protection against hostile in-process code. Use one session per sequential operation; concurrent requests use independent sessions. Connection/transaction access is trusted harness access, not an untrusted API.

`PostgreSqlExternalStaffIdentityResolver` implements the existing Identity Application contract, queries only Identity issuer/mapping/staff tables with parameterized exact keys, and requires registry enabled, mapping active and enabled/nonzero staff. Missing or ineligible mappings yield no staff. It checks for a second row rather than selecting an arbitrary first match; uniqueness normally makes ambiguity impossible. No email, actor GUID, tenant/branch selector or provider organization claim is an alternative key. Fully materialized immutable outputs compose with unchanged `AuthenticatedActorBoundary`. Only the persistence test assembly gained friend access to create synthetic validation evidence. Infrastructure and API do not gain evidence issuance or DI registration.

The existing offline tool adds `mapping-script`. `rls-script` is now bounded to the original second migration so it cannot silently incorporate later unrelated DDL (BUG-009/FIX-009). Non-CI `apply` and `bootstrap` fail closed before migration: applying this slice to the preserved development database requires separate review. Fresh disposable `ci-bootstrap`, separate migrator verification and existing-schema bootstrap rejection are exercised locally.

## Remaining security gates and next slice

No real protocol validation, provider SDK, persistent production identity enrollment, login, middleware, endpoint, runtime bootstrap route, account linking, invitation, delegation or patient data. Database mapping does not prove authentication. Internal constructors/friend access are composition controls, not a sandbox against malicious code. Exact tuple uniqueness cannot detect a provider recycling a subject; lifecycle/retention and provider account-reuse safeguards remain required. Enterprise upstream provenance/assurance is not present in key-only evidence.

Issuer/mapping disablement is visible to new snapshots; already open Repeatable Read snapshots can retain earlier eligibility. Mapping revisions are not organization authorization revisions, and no session revocation or immediate global disablement is claimed. Reader RLS/context-forgery limits from ADR-006 remain.
