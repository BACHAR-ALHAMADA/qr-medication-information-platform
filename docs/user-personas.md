# User personas and research assumptions

These are provisional research lenses, not validated demographic profiles. Do not infer capability from age, language, or disability. Use synthetic examples only (REQ-009).

| Research group | Need to investigate | Design implication to validate |
|---|---|---|
| Patient using a phone | Find understandable, relevant medication information after a scan | Calm mobile entry, clear information hierarchy (F-001) |
| Older adult | Text, device familiarity, dexterity, confidence, and recovery needs vary | Large text, understandable controls, forgiving navigation (F-003) |
| Person with limited English proficiency | Preferred language, medication terminology, and translation trust | Discoverable language selection and medically reviewed content; include RTL users (F-003, F-004) |
| Person using assistive technology | Reading order, control names, focus, contrast, reflow, and alternative formats | Test actual assistive technology use, not only automated checks (F-003) |
| Pharmacist | Work context, responsibility, time pressure, and content trust | Research core tasks before defining dashboard functions (F-002) |
| Supporting caregiver | Help someone navigate general information | Public access may help; private proxy access is not assumed or approved |

Validate these assumptions through the [UX research approach](ui-ux-blueprint.md). Recruitment and reviewer availability need HUM-009. Patient accounts, caregiver delegation, and professional roles beyond validated workflows are not approved requirements.
